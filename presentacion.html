1. Intención del Proyecto

El ADR Security Validator es un asistente de arquitectura diseñado para cerrar la brecha entre la toma de decisiones y la seguridad proactiva.

  • Propósito: Analizar los Architecture Decision Records (ADRs) en busca de vulnerabilidades antes de que se escriba una sola línea de código.
  • Problema: Las decisiones de diseño inseguras (como bases de datos sin SSL o contraseñas en código) suelen detectarse tarde en el ciclo de vida.
  • Solución: Una IA entrenada que conoce miles de decisiones previas y reglas de seguridad modernas.

2. ¿Para quién va dirigido?

Arquitectos de Software

Para validar que sus decisiones cumplen con el Well-Architected Framework.

Líderes Técnicos

Para asegurar consistencia en múltiples proyectos y evitar contradicciones históricas.

DevSecOps

Como una primera capa de defensa en la fase de diseño (Shift-Left Security).

3. Arquitectura del Sistema

El proyecto se consume localmente en Obsidian, pero procesa todo en la nube de AMD Developer Cloud.

  • Frontend (Local): Plugin de Obsidian desarrollado en TypeScript que ofrece validación bajo demanda.
  • Cerebro (AMD Cloud): Modelo Qwen3-8B optimizado con Fine-tuning sobre hardware AMD Instinct™.
  • Memoria (Vector DB): Qdrant almacenando +2000 ADRs reales de Kubernetes, Django y Rust RFCs.

4. Componentes y Archivos

Backend (FastAPI)

backend/main.py: El orquestador que une la IA con la búsqueda vectorial.

backend/requirements.txt: Configuración exacta para ROCm 6.2 y Torch 2.5.

Inteligencia (Qdrant)

backend/qdrant_setup.py: Script de indexación semántica con el modelo Qwen3-Embedding-8B.

docker-compose.yml: Gestión persistente de la base de datos vectorial.

Fine-tuning (Training)

fine-tuning/fine_tune_qwen3_8b.py: Script de entrenamiento optimizado para MI300X.

fine-tuning/training-data.jsonl: Dataset con patrones de seguridad (OWASP, Bandit).

5. El Proceso de Fine-tuning

Para que la IA no solo "charle", sino que "analice", realizamos un proceso de entrenamiento especializado:

  • Hardware: AMD MI300X (192GB VRAM), permitiendo entrenamiento en 16-bit (BF16) sin pérdida de precisión.
  • Técnica: LoRA (Low-Rank Adaptation). Solo entrenamos una pequeña capa de adaptadores para inyectar conocimiento de seguridad.
  • Dataset: Combinación de ADRs aceptados y ejemplos de código vulnerable.
  • Optimizaciones: Parches específicos para Python 3.12 y drivers ROCm para maximizar el uso de los núcleos de AMD.

6. El API y Consumo

La API de validación es sencilla pero potente:

POST /validate-adr

{
  "title": "Usar MongoDB",
  "content": "Almacenaremos contraseñas en config.py"
}

Respuesta: El sistema devuelve un JSON con el estatus, riesgos de seguridad detectados por reglas, contradicciones halladas en Qdrant y la AI Critique del modelo entrenado.

7. ¿Por qué Qdrant?

Usamos Qdrant para dotar a la IA de "memoria histórica".

  • Convierte el texto en vectores de 4096 dimensiones.
  • Permite encontrar en milisegundos si alguien en el pasado ya rechazó una idea similar.
  • Asegura que el nuevo diseño no contradiga los estándares establecidos por la comunidad (ej. Kubernetes).
